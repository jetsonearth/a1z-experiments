# 单次回放准备

2026-10-02：`replay.py` 已部署到 Jetson，本机和 Jetson 默认离线检查通过。没有启动电机；原位保持与实际回放均未验证。

## 下一次现场顺序

1. 清空周围空间，布置能承接失能臂体的支撑；操作者到场。当前位置控制和退出行为未经实机验证，不能假定会悬停。
2. 先执行 `--execute hold`：现场输入 READY 后，以当前角度为目标，3 秒渐增至 SDK 默认 PD 参数，1 秒稳定观察，5 秒倒计时后失能。总计约 9 秒；不会走示范路径。保留当前 0.3 重力补偿与力矩前馈上限，未重新标定腕部相机负载。此步用于检验是否能稳定保持，不保证成功。
3. 检查 `replay-results/` 的实测/目标角度、反馈年龄、故障和停止结果，并由操作者确认实际停止表现。通过后才进行回放。
4. 手动准备接近源轨迹起点的姿态；程序不会自动接近起点。回放开始前误差大于 0.05 rad 即拒绝。路径需现场检查，软件尚无碰撞检测。
5. 再执行 `--execute replay`：3 秒增益渐入并衔接允许的小起点误差、1 秒等待、13.47 秒轨迹、5 秒终点保持后失能。仅一次，不循环、不回零、不控制夹爪。Ctrl+C 中止也会失能。

首测入口通过每关节反馈新鲜度、控制周期与跟踪偏差检查；跟踪偏差超过 0.15 rad 中止。该值是本次回放测试条件，未用于拖拽采集的速度限制。速度保护使用官方默认值。

默认调用仅检查数据，不构造机器人对象：

硬件测试另加上述明确的 `--execute` 参数并由现场输入 READY。当前网页继续只负责采集与数据回看，没有静默接入实机回放按钮。回放日志包含目标与实测角度；此入口尚未接入回放视频采集，首次现场测试不要声称已获得视频验证。

验证范围：15 项离线测试通过，覆盖采集既有检查、保存、回放输入拒绝、起点误差门槛、插值端点与默认命令不连接硬件。未验证 PD 效果、跟踪精度、实机停止表现。
