## 操作入口

双击 `Start.command` 打开 Mac Terminal。它只做前置检查，然后等待操作者按回车。
按回车后立即进入低比例辅助托重和待录，无准备倒计时。按开始前让机械臂靠稳支撑；到机械臂旁后开始拖动即可。任一关节移动至少 0.015 rad 且连续 3 次更新满足时开始录制，保留约 1 秒前段。记录中连续 2 秒没有超过 0.003 rad 的位置变化即保存并停用，不要求录满 20 秒。待录、单次录制各设 2 分钟上限。

用户已确认前次运动为主动托着拖动，因此速度上限从 0.6 调到 1.2 rad/s（约 69°/s），移除相对起点 0.35 rad 限制，保留 SDK 关节范围、反馈超时、温度、故障及力矩限制。结束前放回支撑；运动期间持续托住。触发依据是实测运动，不能区分手动拖动与被动滑落。

停止或异常会失能，**不会保持姿态**。本轮不用位置刚度、不控制夹爪、不做归位／回零／回放。

- 重力补偿 2 秒内从 0 加到 0.3；模型包含 G1Z，腕部相机质量尚未单独校准。
- CAN 指令间隔至少 0.3 毫秒；单关节反馈超时仍为 0.1 秒；无首轮相对起点限制，速度限 1.2 rad/s。
- 请求前馈力矩上限 `[4,4,4,2,0.5,0.5]` Nm，阻尼另计。这些是本轮保守软件界限，不是对实际末端力的保证。
- 退出、异常、到时后发送停用；CAN 断线时软件无法保证停用指令送达，操作者持续支撑。

脚本部署在 Jetson `/home/dimos/a1z-experiments/2026-10-02/teach.py`，数据写在同目录 `episodes/`。Mac 终端镜像写入 `console-latest.log`。

**串口由录制窗口独占时，不要运行其他串口助手或 screen。** 在窗口等待／录制时，Codex 只能读取本地日志；窗口结束并退出后才重新连接串口读取 episode。

## 数据边界

约 50 Hz 记录单调时间、六关节 q/dq/effort、状态码、反馈年龄与计数、重力比例及实际发送的 MIT 参数。没有同步图像或夹爪状态，不是可直接训练 HIL-SERL 的完整 transition。
Jetson 系统日期与 Mac 不一致，保留其未校准原值，时序分析使用单调时钟。文件名用实验日期、单调计数与 PID，避免把错误日期当成采集日期。

完成录制后先核对时间顺序、反馈新鲜度、关节变化、停机原因和实际采样间隔。禁止自动回放。

## 首次录制失败与修复证据

首轮只录到 10 帧，第 6 关节反馈间隔超过 100 ms 后停用，不计作成功示范。
对照试验（不调用使能、零位置增益、请求零力矩）：

| 发送方式 | 每关节反馈数 |
|---|---|
| 原顺序密集发送 123 轮 | 123, 123, 123, 123, 123, 0 |
| 逆序密集发送 123 轮 | 六关节均 123 |
| 原顺序、帧间隔 0.3 ms，123 轮 | 六关节均 123 |

独立入口加入帧间隔后，在真实硬件连续检查 8.003 秒、1,965 轮，六关节各返回 1,965 帧，最大反馈年龄约 4.17 ms。证据支持发送节奏相关丢反馈；未独立定位到 USB 固件、内核驱动或 CAN 仲裁中的具体一层。没有升级内核，也没有放宽 100 ms 保护。
用户指出按回车后应有走到机械臂旁的时间，已加入 20 秒准备和运动触发待录。新流程的完整实机拖拽录制仍待完成。

最新交互已替换此前的 20 秒准备和固定时长方案：立即待录、运动触发、静止 2 秒结束。九项逻辑测试通过；完整实机示教仍待操作者完成。

## 18:43 联合录制中断与修复

首次联合尝试显示录制到至少 244 帧关节反馈，静止两秒正常结束；随后在 `camera.stop()` 等待期间收到 SIGINT，`KeyboardInterrupt` 导致主进程退出 -2。旧逻辑在相机收尾之后才保存关节，因此本次关节 JSON 未落盘且无法恢复。相机保留 211 帧、约 7 秒的 H.264，解码帧数一致；视频收尾日志仍记录中断，不把本次标为完整示范。
