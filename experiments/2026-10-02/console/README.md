# A1Z Console

Design: Nothing design language (Space Grotesk / Space Mono / Doto from Google Fonts, system fallbacks offline; OLED-black dark mode, off-white light mode via prefers-color-scheme). The older serial-based collection studio (`studio/`, `Start Studio.command`) is unchanged.

Web front end for evaluation, HG-DAgger collection and control-layer tests. The dashboard shell runs on the Mac; robot APIs and experiment data remain on the Jetson.

**Start:** click the existing Dock `A1Z Console.app` or double-click `A1Z Console.command`. Both open `http://localhost:8780/#/run` without waiting for Jetson and without connection alert dialogs.

`launcher/local_dashboard.py` serves the existing assets on Mac loopback port 8780. Its background worker tries `jetson-direct`, then `jetson`, starts only the remote HTTP server if needed, and tunnels through Mac loopback port 18780. Offline pages remain navigable; controls and live readings are unavailable. Session polling restores the page automatically on reconnect. No robot session is started, READY sent, or failed POST queued/replayed by the launcher. Requests retain token checks and video Range headers.

The installed Dock app executable is copied from `launcher/launch.sh`; it uses the repository's local server. Launcher log: `~/Library/Logs/a1z-console-launcher.log`. App launch does not require an Ethernet connection; controlling the robot still requires the Jetson API connection.

Validation 2026-10-08: four loopback integration tests (`cd launcher && python3 -m unittest -v test_local_dashboard.py`) cover offline loading/no command replay, authenticated forwarding, access boundaries and video ranges. Installed Dock app opened the dashboard in Chrome with Jetson network unavailable; Run and Runs navigation verified. Actual network reconnection and physical control have not been verified this session.

**Pages** (UI in English since 2026-10-05; the client output box still shows the scripts' Chinese terminal text): run console (live wrist camera, start/READY/trial keys, labels, `i` reference pose, client output, temperatures) · runs (all sessions, per-trial error vs the hand-inserted reference, video, relabel / exclude) · report (model × stiffness × integral, rates with 95% Wilson intervals, median error) · models · data · hardware (gripper / joint temperatures) · cameras (HIL-SERL side camera: live view whoever holds the camera, start/stop a preview in tmux `sidecam`, drag the classifier crop and save it to `2026-10-09-hilserl/cameras.json`; added 2026-10-10, tested against a fake frame on the Mac, not yet on the Jetson). The overview page is hidden (commented out) since 2026-10-05 because Run / Runs / Report duplicate it.

**New session form (2026-10-10):** the four hard-coded mode tabs became a program picker driven by `GET /api/programs`; `server.py` holds a `PROGRAMS` registry (id, label, one-line description, the `inputs` it needs such as `model` / `epoch`, optional `advanced`, `launch`, `detect`) and `INPUTS` (how each input is rendered), so a new program is one registry entry and no UI code. Stiffness, integral ki, cap and grip hold are no longer on the form: the start request omits them and the server applies its defaults (dimos gains, ki 2, cap 1 deg, grip hold 1.5 N m); a closed Advanced disclosure can override them for one start and is not remembered (old `a1z-run` values are dropped). A server without `/api/programs` (404) makes the page fall back to the original four programs. Verified 2026-10-10 offline only: for ten request shapes the new `start_session` builds the same eval.sh / tmux commands as the previous copy (the only difference is an explicit `--grip-hold 1.5` when the field is omitted, equal to the client script's default and to what the old page sent); the page was driven against a stubbed `server.py` on a spare port (registry picker, declared inputs only, request bodies, 404 fallback, localStorage cleanup, an extra registry entry rendering without UI changes); launcher tests pass. Not verified: this was not deployed, so the Jetson still runs the previous `server.py` (and the page uses the fallback list) until it is copied to `~/a1z-experiments/2026-10-02/console/server.py` and the console server restarted; no real session was started, and the run-time control buttons are still per-mode (a new program gets the generic eval-style controls).

**How it drives the robot:** it creates the same tmux session as `eval.sh` (`A1Z_NO_ATTACH=1`) and types keys into the client window; robot_proc.py's safety layer and all files are unchanged. `ssh -t jetson-direct tmux attach -t eval` still works. READY is only sent when the operator clicks it while the client is waiting for it. The gripper over-temperature lock (≥ 88 °C coil) is a page-side guard on the start buttons.

**Writes:** only `operator_label` / `excluded` edits in trial JSON, recorded in `console_edits` with `edited_via: console`.

Verified 2026-10-05 without motors: all pages against real session data, video playback with seeking, starting an eval session up to the READY prompt, cancel, close. Not yet verified with the arm enabled.
