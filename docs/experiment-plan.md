## 0. 先验证一个技术假设，暂不锁定算法或采购

**目标是找到值得押注的机器人教学范式。撤回上一版把 ACT 写成已选主线的决定。** 当前建议优先评估 HIL-SERL 式“少量示范 + 真机交互 + 人工纠正”的可行性；这是第一轮候选，尚未成为用户确定的公司技术路线。没有必要先完成 ACT、DP、DAgger，再获得尝试 RL 的资格。

### 两条路线对应的假设

| 候选 | 要验证的产品假设 | 需要付出的主要成本 |
|---|---|---|
| UMI 式采集与策略学习 | 人脱离机器人也能自然、快速地采到可迁移示范，降低数据获取和扩展任务的成本 | 采集硬件、观测与动作表示、机器人端适配和策略训练 |
| HIL-SERL 式交互学习 | 少量初始示范配合现场试做和纠正，能减少达到可靠执行所需的人与工程时间 | 接触控制、训练环境、奖励、复位、接管与在线训练 |

两者涉及不同环节，可以组合；首轮不实现组合系统。买到 UMI 不等于买到 A1Z 可执行的策略，学过一篇 RL 论文也不等于硬件已支持它。

### 近期建议：优先评估 HIL-SERL，先安排两个工作轮次检查可行性

暂定任务为同一根 USB-C 线、同一固定插座、插头已夹好、从近距离开始的局部插入。拔出与复位单独验证；允许先人工复位，但必须计入人工成本。不包含找线、抓线和理线。

- [ ] 查明 A1Z 能否稳定执行受限的小幅动作，接触时如何中止，控制与反馈是否足够。
- [ ] 确认相机视野、同步观测，以及任务成功／失败／中止信号。
- [ ] 明确每次尝试如何复位，测人工复位需要多久。
- [ ] 确认策略与人工接管的切换机制；SpaceMouse 未到时先准备接口并完成静态检查，不在活动的位置控制下直接用手抢控制。
- [ ] 列出训练环境与原方法之间的差异、算力和实现缺口，估算是否值得投入。

这两个轮次的交付是**可做／暂不可做及具体缺口**，不是承诺两轮就能训练成功。若主要成本将耗在重做接触控制和硬件适配上，先暂停该路线；这只说明当前设备的实验成本高，不能据此否定算法。

可行性通过后，建议为一个完整的“初始示范 → 交互与纠正 → 独立评测”试验约定时间预算；可先以两周作为讨论用的上限，而非完成承诺。实现与学习耗时分别记录。试验前确定任务变化范围、验收标准及人工预算，期间不因新论文反复换方法。

观察重点：同等条件下，学习前后的自主成功率、接管和复位总时间，以及一次小幅换位后的追加示教与工程成本。人的纠正完成一次任务，不等于策略已经学会；需要再做不接管的评测。未完成硬件适配时，不给学习方法下结论。

**UMI 暂不采购。** 当现有拖拽／遥操作实测显示，主要瓶颈是采集慢、机器人必须被占用、需要多人多场景收集数据时，再核对 UMI 与 A1Z 的相机、夹爪、动作和训练链路适配，决定是否借用或购买。

依据：[UMI 原始项目](https://umi-gripper.github.io/)；[HIL-SERL 原始项目](https://hil-serl.github.io/)。HIL-SERL 的起点可为少量示范及在线交互，不要求先有 ACT 策略；它也不等同于专指对预训练 VLA 做 RL post-training。

## 0.1 HIL-SERL 的 starting point

原版 HIL-SERL 训练面向具体任务的视觉 RL 策略，不要求先有一个 VLA、ACT 或能自主插入的策略。它仍然需要训练；这里采用的是示范辅助的在线 RL，而不是对现成 VLA 做后训练。

| 部分 | 新实验开始时是什么 |
|---|---|
| 视觉特征 | 论文采用 ImageNet 预训练的 ResNet-10；提供图像表示，不自带机器人插接能力 |
| 动作策略 actor 与价值网络 critic | 新建并初始化任务网络；首次实验不加载已学会 USB 插入的策略。恢复同一次训练时才读取该次 checkpoint |
| 初始示范 | 少量可执行动作的完整 transition，装入 demo buffer；装入数据不等于已经把策略训练好 |
| 成功判定 | 事先验证的奖励函数。原实现训练成功分类器；本实验若有可靠电气信号，可评估替换并明确记录偏离原方法的地方 |
| 执行条件 | 能受限执行动作的控制器、可复位的工位、可接管的人，以及明确的任务边界 |

训练时利用示范和新的实际交互更新策略与价值网络，人的纠正也成为训练数据。首次新建策略可能给出无用动作，必须先通过控制与接管条件，不能把未训练策略直接用于无约束接触探索。

方法依据：[论文 §3](https://arxiv.org/html/2410.21845v3#S3)、[模型创建实现](https://github.com/rail-berkeley/hil-serl/blob/main/serl_launcher/serl_launcher/utils/launcher.py)、[训练入口](https://github.com/rail-berkeley/hil-serl/blob/main/examples/train_rlpd.py)。后续若改为 VLA 初始化、BC 预热或残差策略，应另记为方法变体，不悄悄混入本轮结果。

- 记录单调时间、q/dq/effort、反馈年龄／计数和实际发送参数，保存在 Jetson 实验目录的 `episodes/`。不采相机／夹爪，本轮数据只是轨迹验证素材。
- Jetson 系统日期与当前实验日期不一致。保留未校准系统时间供追溯，采样时序使用单调时钟；本轮未修改系统时钟。
- 终端持有串口期间，其他助手不得同时连接或发送 Ctrl+C。先读 Mac 本地 `console-latest.log`；终端结束后才重新连接取回 episode。

## 3. 近期准备与后续衔接：按完成条件推进

前面三轮可在 SpaceMouse 到货前逐步准备；第 4 轮要等学习与评测链路就绪。每轮建议 1–2 小时，不要求每天全部完成，卡住时写下唯一阻塞项。

### 第 1 轮：空中拖拽 → 轨迹检查 → 空中回放

执行 §1。暂时不需要完整手眼标定、LeRobot 插件、VR 或训练 GPU。相机还没调通也能先验证关节轨迹链路，但这时的数据仅是轨迹验证素材。

### 第 2 轮：补相机，把三条示范录完整

- [ ] 在 Jetson 本地保存 D405 RGB 与关节状态，给每帧加时间戳；深度若可用一并保存其比例和相机内参。
- [ ] 先录三条同类短示范，逐条回看。手尽量握在不遮挡腕部相机的位置；仍有遮挡就如实标记，不隐去失败样本。
- [ ] 用一个明显的短暂停顿或方向变化，检查视频与关节曲线的时间对应关系。记录相机时钟与主机时钟的映射／偏移，不能只用帧序号拼接。
- [ ] 检查实际采样频率、最长间隔、缺帧、静止重复帧、图像是否看得到目标。关节约 50 Hz、RGB 约 30 fps 可作为试录目标，不视为实测保证，也不要求两者逐帧等频。

**通过条件：** 三条数据都能离线打开、查看图像并对应关节运动；质量有问题先修采集，再采更多。此时才进入任务数据收集。

### 第 3 轮：固定工位的 USB 接近，再决定接触段

**主任务采用实际 USB 线的插头，预先固定在夹爪中；插座固定在底板上。** 先不包含从桌面抓线、理线和换握。固定插头只是缩小任务范围，不能当成已经解决柔性线缆操作。

- [ ] 记录插头类型、夹持方式、插座位置、线缆余量和相机视野，拍一张装置照片。用可替换接头／延长线作工装。
- [ ] 拖拽示范从已知起点接近插座，在尚未接触的位置停下。先检查、再做单次低速回放；连续三次接近均无异常后再讨论接触。
- [ ] 核对当前 A1Z 控制接口能提供什么：位置／速度限制、跟踪误差、effort 反馈和中止机制；为这套实物明确行程、超时与异常阈值，并先验证中止行为。
- [ ] 条件具备后，人工在已验证的拖拽模式下示范插入，标注接近、接触、完成与退出。记录人是否额外扶插头、扶插座或拉线；这些帮助不算机器人能力。
- [ ] 自动插入先单次验证，不能把人的接触轨迹交给高刚度位置回放后直接循环。接触条件未验证，就先用宽松插销或继续做无接触接近。
- [ ] 检查完成信号：U 盘可使用识别事件；USB 线需按实际连接设备选择电气／充电／检测信号，不能默认任意线都会枚举出 USB 设备。电气连接、机械到位和无损伤分别记录。

**通过条件：** 明确当前完成到哪一段、哪些段自主、哪些段依赖人，保留每次尝试。前 5–10 次用于调试，不作为泛化或生产可靠性的证明。

### 第 4 轮：策略基线跑通后，加入一种变化

选定候选并跑通一个完整学习实验后，再选一种已评估可行的小幅起点或插座变化，保留原位作对照。记录策略对该变化的成功率和新增示范成本；不刻意让固定回放撞向偏移后的插座。

- [ ] 若变化导致目标观测或定位失败，先检查图像与训练覆盖；有明确需要时只增加一个显式视觉对准方法，并单列其工程成本。
- [ ] 需要把图像位置转换成机器人运动时，再做相机与机械臂坐标关系的标定，并独立检查定位误差。
- [ ] 单独记录视觉对准与接触插入的失败，判断下一步真正缺什么。
- [ ] 同步取得连邦真实接头、插座、锁扣和工序信息，不等所有学习算法试完再接触客户样品。

## 4. 拖拽数据能不能训练？可以，但先明确观测和动作

Kinesthetic teaching 是可用的示范方式。SpaceMouse 不是模仿学习的硬性前提；它主要提供一种不直接碰机械臂的控制与接管输入，是否更省时间要实际比较。

拖拽时，人的外力推动机械臂，实测关节运动和机器人发出的控制指令不一定相同。不能把重力补偿指令当作专家位置动作，也不能把人在接触中施加的力从关节轨迹里直接还原。

| 最小数据 | 记录要求 |
|---|---|
| 实测关节状态 | `q`、可用的 `dq`、时间戳、反馈有效性；角度单位明确为 rad |
| 视觉 | RGB、帧时间戳；可用时加深度、比例和内参；保留原始数据 |
| 夹爪与装配 | 有效反馈与命令分开；若全程固定夹持，记录固定状态与装配照片 |
| 动作来源 | `kinesthetic`／`teleop`／`policy`；原始命令单独存，不把反馈伪装成命令 |
| 阶段与结果 | 接近／接触／退出、成功／失败／中止、人工扶线或扶物、失败说明 |
| 复现信息 | SDK 提交、配置、工件／位置编号、episode 编号、操作者、标定版本 |

**若选择关节位置策略：** 可以从未来实测关节轨迹构造目标动作，明确时间偏移、重采样方式与控制周期。这属于离线生成的动作标签，必须先检查该目标轨迹在实际执行器上的可跟踪性；不能默认直接可训可用。训练时没有的触觉、手部遮挡和人工扶物，都可能造成示范与执行之间的差异。

### 选择具体方法以后，再按它的接口采训练数据

今天的短轨迹用于检查硬件、录制和可执行性，可以开始做，但不要预先采几十条并假定任何方法都能直接使用。

若可行性检查后选择 HIL-SERL：先确定控制动作与频率、观测、奖励、终止条件、复位和接管接口，再记录能形成 `(observation, action, reward, next_observation, termination)` 的交互数据。拖拽得到的实测位置不能自动冒充控制器实际执行的动作；如要转换初始示范，必须验证动作含义与执行的一致性。初始数据量参考实际质量与方法要求确定。

ACT 保留为可能的 IL 对照工具，不是强制前置课程。是否需要它，应由本轮需要比较的问题决定，不能为了完整而再增加一条实现路线。

## 6. 技术 bet 与后续选择

**长期产品假设：** 少量示范与局部纠正能够降低新插接任务的部署成本。先让一个范围明确的试验检验一条候选路线。显式物体相对关系、视觉对准与可复用接触技能仍是后续候选结构，尚未由本实验验证。

| 观察到什么 | 下一步 |
|---|---|
| 固定工位已经够用，换型也很快 | 尽早测第二个工件／连邦样品，记录复用成本 |
| 插座一移动就找不到目标 | 先查视野、标定和定位；选择一个视觉调整方案 |
| 已对准但接触动作反复失败 | 查夹持、工装、可观测性和控制能力，再决定是否需要学习接触策略 |
| 观测与控制够用，示范规律仍难以手写 | 用同一数据协议试一个 IL 策略，与现有基线比较 |
| 策略已能工作，少数失败可由人纠正 | 收集纠正数据；在未参与纠正的条件下验证收益 |
| 交互学习符合待验证假设，且控制、奖励、复位和接管条件已确认 | 可直接做 HIL-SERL 式试验，无需先完成其他算法；控制器不稳定时停止该分支 |

第二个对象／工位的测试允许重新示教；新增代码、标定、夹具和调参全部计时。若反复需要大量定制工程，应调整假设。不要将同型号换一个位置、新型号接头和完整线缆操作混成一个“泛化”数字。

连邦先用真实样品验证局部插接，再加取线、两端处理、拔出、放置与检测。几份讨论稿对首阶段是否含电气检测的定义需要统一；坏线被正确识别为 FAIL 可以是工艺成功。

## 9. HIL-SERL 从零准备到独立评测的执行顺序

以下是针对 A1Z 的实施设计；每一步未勾选就表示尚未完成。论文与官方教程可参考，但不证明 A1Z 已经兼容。建议由 Codex／实现侧负责适配、数据检查和训练，用户负责现场示范、接管、复位与装置确认。

### H0 · 固定任务与评测约定

- [ ] 只训练固定夹持后的局部 USB-C 插入，记录插头／插座型号、装置照片、起点范围和夹持方式。拔出先作为独立复位步骤。
- [ ] 写清自主成功的判据、最长尝试时间、允许重试次数；分别计插接成功、电气连接与异常损伤。
- [ ] 约定初期调试与最终评测条件。建议先 10 次调试，再对选定 checkpoint 做 50 次独立评测；这是本项目建议，不是可靠性保证。
- [ ] 为平台适配和在线学习分别计时；试验前确定继续投入的成功率、人工负担和预算标准。

完成证据：一页任务约定；所有数值与工件条件已填，没有待定的执行参数。

### H1 · 通过 A1Z 硬件与控制检查

- [ ] 完成 §1–§3 的连接、负载、反馈、停止、同步采集和单次运动检查。
- [ ] 建立并验证受限动作接口：动作单位、坐标系、更新频率、速度／目标偏移／工作空间边界、接触异常中止。
- [ ] 验证初始姿态、进入任务区域与退出路径。人工复位可用，但要明确控制停止与重新开始的状态，不把人移动工件时的数据混入任务 transition。
- [ ] 审查超时、反馈丢失、推理超时、通信断开和程序退出的实际行为；只有一个进程拥有机械臂控制权。

完成证据：单次受限执行与中止日志。只读状态、能拖拽或能回放，都不能单独替代这个条件。

### H2 · 适配训练环境与算力，先离线检查

- [ ] 固定官方代码提交和依赖版本；新增 A1Z 环境适配，不直接启动 Franka 控制服务。
- [ ] 实现训练环境的 observation、step、reset 和结果信息：图像、所需本体状态、实际动作、奖励、成功／失败／中止／超时。明确跨 episode 的数据边界与训练 mask 含义。
- [ ] 初版固定夹爪，不额外学习抓取；拟使用局部末端增量接口，具体自由度、缩放和频率在 H1 验证后确定。不能把此前 ACT 的关节目标标签直接当成该接口的动作。
- [ ] 核对原实现需要的本体反馈；A1Z 缺少的量不能伪造为零当有效传感器。增删观测作为适配差异记录。
- [ ] 用保存的观测和受控测试数据验证环境形状、单位、数据存取、策略推理及一次 learner 更新；检查数值有限、参数确实更新、checkpoint 能重载。
- [ ] 确定 learner 使用的兼容 GPU／JAX 环境，测显存和更新速度；不默认 Mac 或 Jetson 已具备兼容训练环境。原项目推荐 GPU。
- [ ] 明确 actor 推理运行位置及其到 Jetson 控制服务的延迟；控制回路留在硬件侧。如果 learner／actor 分机运行，验证数据传输和参数同步。本地网络与互联网分开考虑；原有串口不承担训练数据传输。

完成证据：环境检查报告、一轮离线更新及 checkpoint、主机分工和实测延迟。此阶段不让随机策略在机械臂上探索。

### H3 · 建立并单独检验奖励

- [ ] 先检查实际装置是否能可靠读到连接信号。若采用它，分别测试完全插入、半插、接触抖动、断开及错误位置；电气接通不能自动等同于机械完全到位。
- [ ] 若无法直接可靠判断，采成功与未成功画面训练分类器。困难负例包括接近插口、半插和遮挡，不能只用空桌面负例。
- [ ] 留出独立 episode 检查误报／漏报，尤其误报成功；确认终止信号与标签对应真实任务结果。奖励不可靠先修奖励，不启动 RL。

完成证据：固定版本的 reward 与独立核验表；选用电气信号或分类器的理由已记录。

### H4 · 验证人工接管，收集初始示范

- [ ] 先在无接触条件验证策略、人和停止状态之间的切换；测试接管、释放和中止时不会有两路指令竞争。
- [ ] 先采 3 条符合环境动作定义的完整示范，逐条检查 observation → 实际执行 action → next observation → reward／termination 的时间关系。
- [ ] 通过后，按任务覆盖采第一批成功示范。可先以 20 条作为工程起点，依据官方 RAM 教程；A1Z USB-C 所需数量仍由实测决定。
- [ ] 标记人是否额外扶线、扶插座或调整夹持；失败尝试保留为诊断数据，成功示范另行筛选。
- [ ] 将检查通过的示范装入 demo buffer，检查能采出有效训练 batch。

**SpaceMouse 未到时：** 可以做 H0–H3 中不依赖遥操作的工作，采奖励图片，并用少量拖拽记录验证观测链路。若要把拖拽示范作为 RL 初始数据，须证明重建的动作符合 H2 的控制接口与转移语义；未经验证不批量导入。完整在线训练应等一个已验证的接管接口就绪；SpaceMouse 是当前较直接的候选。

完成证据：示范数据检查报告、非空 demo buffer、接管切换日志。

### H5 · 初始化新策略，短时试运行训练闭环

- [ ] 记录随机种子、视觉权重来源、环境配置、demo 路径；使用新的实验目录，避免误恢复旧 checkpoint。
- [ ] 新建任务 actor／critic，加载预训练视觉部件；首次实验不要求 VLA 或 ACT 权重。
- [ ] 核对 `random_steps`、`training_starts`、动作范围与初期人工控制规则。未训练策略与初期探索都必须经过 H1 的限制。
- [ ] 开始少量、有人监督的短回合：确认交互数据进入 online buffer，接管时记录的是人的实际动作，而不是被覆盖掉的策略输出。
- [ ] 确认 learner 从示范与在线数据更新、actor 接收到新参数；检查接管数据进入规定的缓冲区。
- [ ] 保存并重载一个 checkpoint，确认数据、模型与计数能一致恢复。断线／故障先中止执行，不能继续使用陈旧指令。

完成证据：一次完整的数据与参数往返、checkpoint 及日志。尚不能以此声称策略学会了。

实现对照：[train_rlpd.py](https://github.com/rail-berkeley/hil-serl/blob/main/examples/train_rlpd.py)。官方实现使用示范与在线数据各半采样；接管记录进入在线和示范缓冲区。若调整，写入实验配置。

### H6 · 在线学习，记录全部人工负担

- [ ] 按 H0 预算运行短训练块，定期保存策略；记录机器人交互时间、梯度更新次数、实际墙钟时间和工程时间。
- [ ] 在需要时给局部纠正，记录接管次数和秒数；每次复位、扶线和装置调整也计时。人工完成任务的回合不能算自主成功。
- [ ] 定期冻结策略做小批不接管检查；安全中止仍保留，计为失败／中止。用这些检查选择后续 checkpoint，最终保留条件不用于反复调参。
- [ ] 若奖励误报、动作／观测错位、控制异常或长期数值不稳定，先修具体问题，不把问题归结为数据不够。
- [ ] 达到预算或预先约定的停止条件后结束本轮。若只完成适配，如实记录，不据此判定学习范式优劣。

完成证据：训练曲线与人工时间表，包含所有失败。论文报告的训练时长不含我们的全部移植和装置建设，不当作交付承诺。

### H7 · 独立评测，再测试一次变化

- [ ] 固定 checkpoint、环境和奖励版本，关闭学习与人工接管；人工只做约定复位，必要时安全中止。
- [ ] 按 H0 的固定条件报告全部尝试、自主首尝成功率、允许重试后的成功率、超时／中止和含复位的节拍；用独立核验避免奖励误报抬高成功率。
- [ ] 如果没有可安全执行的初始策略，不为了填对照表强行运行随机策略；注明缺少该对照，必要时使用已验证的简单回放／控制基线。
- [ ] 然后单独测试一个小范围位置变化，记录追加示范、接管与工程时间；之后才扩展到第二个接头或连邦样品。

完成证据：独立评测表、视频、适用范围与下一轮继续／停止的理由。一次模型成功不等同于完整线缆工序或可规模化部署。
